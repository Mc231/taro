# Security review (Phase 19.5)

Date: 2026-10-02. Scope: `apps/taro`, `packages/*`, `worker/` at `86a1f55` plus this sprint's fixes. Method: manual review of every trust boundary below, with the existing automated gates as evidence (`check_worker_env.py`, `check_forbidden_apis.py`, `.gitleaks.toml`, the Worker contract and integration suites). The `/security-review` skill over the full diff since Phase 2 has **not** been run yet: it is a MANUAL step for the owner or the verify pass.

Processors at launch: OpenAI only (`ai.disclosedProviders = ["openai"]`, `ai.moderation.provider = openai`, 00_DECISIONS 2026-10-01). The Anthropic adapter is still compiled into the Worker, but no tier routes to it.

## Findings by severity

| # | Severity | Area | Finding | Status |
|---|---|---|---|---|
| S1 | Medium | Worker, DoS / cost | No request-body size limit. Before any handler ran, every route buffered and parsed the whole body: the zod JSON validator did so on every route, and on attested routes the attestation middleware did it again with `c.req.arrayBuffer()` for the client-data hash. Unauthenticated routes were included (`POST /v1/installs`, `POST /v1/webhooks/appstore`). One request with a body of tens of MB used Worker memory and CPU near the isolate limits. | **Fixed:** `src/http/middleware/requestSizeLimit.ts` (256 KiB, empty `413`) is mounted globally after `noCors` in `buildApp`. It checks a declared `Content-Length` up front and counts a chunked body on a clone. It never replaces the request: hono's `bodyLimit` does, and that drops `request.cf`, which turned the `AI_UNAVAILABLE_REGION` gate off for chunked bodies (caught by `readings.test.ts`). The largest legitimate bodies are the webhook payloads (≤ 100 000 characters by schema). Tests: `test/unit/http/requestSizeLimit.test.ts` (declared length, chunked stream over and under the limit, untouched pass-through) plus the region gate in `readings.test.ts`. |
| S2 | Medium (dev tooling) | Worker dependencies | `npm audit` found 5 high advisories in dev-only packages: `undici` 7.29.0 (via `wrangler` → `miniflare`; 10 GHSAs, among them TLS validation bypass and response splitting) and `sharp` < 0.35.4 (libheif, via the older `miniflare` pinned by `@cloudflare/vitest-pool-workers`). None of them ship in the deployed bundle (`npm audit --omit=dev` was already clean). | **Fixed:** `overrides` in `worker/package.json` (`undici` 7.29.1, `sharp` 0.35.4). `npm audit` reports 0 vulnerabilities, and the Worker suite is green on the overrides. Drop the overrides once `wrangler` and `vitest-pool-workers` pin patched versions (`DEPENDENCY_UPDATE.md`). |
| S3 | Low | Client, backup import | `PlatformFileTransfer.pickJson` read the whole picked file into memory before the 20 MB check in `BackupValidator`. Picking a multi-GB file could crash the app with out-of-memory. Only the user's own choice can trigger it. | **Fixed:** a file whose `length()` is over `BackupSchemaV1.maxFileBytes` is streamed only until it passes the limit, and the validator then reports `tooLarge` as before. Tests: `platform_file_transfer_test.dart` ("a file over the limit is read only past the limit", "a file of unknown length is read whole"). |
| S4 | Low | Client logging | The `Redactor` truncates install IDs only under known keys (`installId`, `X-Taro-Install-Id`). A bare UUID in free text survives. No call site logs one today (grep of `logger.*` calls), and the Logger port forbids it. | Open (accepted). Callers stay responsible, and the review grep is repeated each release. |
| S5 | Low | Worker, store JWS | `AppleJwsVerifier` checks the chain to the pinned Apple Root CA G3, the OIDs, validity dates and the ES256 signature, but not revocation (no OCSP). This is the same trade-off Apple's library offers offline. The purchase path also fetches the transaction from the App Store Server API, so a revoked leaf alone cannot mint credits. | Accepted (documented). |
| S6 | Low | Worker, debug bypass | `isDebugAttestation` compares with `timingSafeEqual` after `utf8()`, so the comparison can leak the token length. The token exists only where `ALLOW_DEBUG_ATTESTATION = "true"` (dev, staging), is at least 16 characters, and prod refuses to start with it (`assertEnvironment`, `check_worker_env.py`). | Accepted. |
| S7 | Info | Android purchase binding | A Play `obfuscatedExternalAccountId` mismatch is logged and counted but never blocks (RC9 by design). iOS binds hard (RC85). | By design. |
| S8 | Info | Dart dependencies | `flutter pub outdated --show-all --json`: 213 packages, none discontinued, retracted or affected by a pub.dev advisory. | Clean. |

No high or critical findings.

## Checklist (Sprint 19.5)

| Item | Result | Evidence |
|---|---|---|
| No secrets in the client (AR17) | Pass | `config/{dev,staging,prod}.json` hold only public IDs and URLs. `git grep` for OpenAI, Anthropic, Google API keys and PEM private keys outside tests finds nothing, and gitleaks runs in CI. Install secret and session token live in Keychain (`first_unlock_this_device`) or Keystore (`flutter_secure_store.dart`). |
| Redactor covers sensitive fields | Pass (S4 noted) | `apps/taro/lib/services/logging/redactor.dart` (content keys, install-ID keys, `*token*`/`*secret*`/JWS/attestation keys, bearer, JWS and blob patterns). Worker `src/logging/redact.ts` plus `inst8` in the request log. |
| Install ID and tokens not in logs, analytics, crash keys, backups or ad requests (02 §16) | Pass | Crash keys: locale, sync status, redacted last route (`firebase_crash_reporter.dart`). Backups: 02 §12 "never included" list, enforced by `backup_schema_v1.json` `additionalProperties: false`. Android `full_backup_content.xml` / `data_extraction_rules.xml` exclude secure storage and `taro_device.db`. iOS marks the device DB `isExcludedFromBackup` (`AppDelegate.swift`). Ads get no identifiers from the app. |
| Prod rejects the debug bypass; no test-only vars in prod `wrangler.toml` | Pass | `identityDeps.ts` `debugAttestationToken` (needs `ALLOW_DEBUG_ATTESTATION === "true"`). `tools/check_worker_env.py` → `OK`. |
| No admin HTTP route; credit transfer needs `transferToken` (RC84) | Pass | `buildApp` registers only health, config, attest, installs, balance, installs/me, purchases, rewards, readings, reading reports, AdMob SSV and webhooks. Admin is CLI-only (`src/admin/*`). `monetization/transferToken.ts` checks an HMAC in constant time. |
| Re-registration of a known install ID without its secret fails (RC54) | Pass | `InstallService.provesOwnership`: SHA-256 of the presented secret compared in constant time, else an App Attest assertion with the previous key (iOS). Otherwise refused. |
| CORS block; webhook signatures | Pass | `noCors` (any `Origin` → empty 403, `noCors.test.ts`). App Store: x5c chain to the pinned G3 root plus OIDs (`AppleJwsVerifier`). Play RTDN: Pub/Sub OIDC RS256 with issuer, audience, `email` and `email_verified` checked before the body is read (`GoogleJwksOidcVerifier`, rate-limited JWKS refetch). AdMob SSV: ECDSA over the raw query, with `user_id == custom_data` bound to the reward intent. |
| Purchase verification | Pass | iOS: server-side `getTransaction` by numeric ID (`^\d{1,40}$`), `transactionId` echo check, `purchases.allowedBundleIds`, environment (sandbox capped per RC63), `appAccountToken` binding (RC85). Android: `purchases.products.get` with URL-encoded path parts, state and consumption checks, server acknowledgement (RC10). Exactly-once grant per store transaction in one D1 batch. |
| SSRF / injection in the Worker | Pass | Outbound hosts are constants (App Store, Play, DeviceCheck, Google JWKS, AdMob keys, OpenAI and Anthropic APIs) or the owner's `ALERT_WEBHOOK_URL` secret. No request value picks a host. Request values reach paths only after a regex or `encodeURIComponent`. All D1 SQL uses bound parameters: the interpolated fragments (`ReadingRepo.first`, `transition` placeholders, `RewardRepo.expireDue` subquery, the metrics `sqlInt`) are constants or generated placeholders. Prompt injection is bounded by the strict output schema, `outputValidator`, the safety prefilter and moderation. |
| Logging of PII | Pass | Worker request log: `{requestId, route pattern, status, latencyMs, inst8, plat, appVer, code}`, never bodies or headers. Client: Redactor on every sink. Analytics are typed events (`ANALYTICS_EVENTS.md`) with no free text. |
| Deep links | Pass | `routing/deep_link_policy.dart`: allow-list of paths, regex-checked IDs (spread, card, journal UUID or date), universal links only on `https://<universalLinkHost>/app/…`. Anything else goes to Home. Links never trigger purchases or readings directly (gates still apply). |
| WebView / in-app browser | Pass | No WebView in the app. `PlatformUrlLauncher.openInApp` accepts `https` only (SFSafariViewController / Custom Tabs), and `open` only `UrlLauncher.allowedSchemes`. URLs come from bundled content or the config, never from AI output. |
| Backup import parsing | Pass (S3 fixed) | Size cap (now also before reading), JSON parse in an isolate, format and version checks, JSON Schema with `additionalProperties: false`, card IDs checked against the deck, JCS SHA-256 checksum, a single drift transaction. Nothing reaches the Worker. |
| Transport | Pass | Android `cleartextTrafficPermitted="false"`, with cleartext only for the dev flavor (`build.gradle.kts`). iOS has no ATS exceptions. |
| `npm audit`, `dart pub outdated` clean at high | Pass | S2 (`npm audit`: 0 after overrides), S8. |
| Python tools | Not audited | `tools/` has no network-facing code. A `pip-audit` run is left for the release checklist. |
