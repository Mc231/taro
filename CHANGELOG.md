# Changelog

All notable changes to the Taro app (`apps/taro`) and its packages (`packages/*`) are documented in this file. Worker changes are in [worker/CHANGELOG.md](worker/CHANGELOG.md).

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). App versions are `X.Y.Z+B`; the build number `B` is monotonic across both stores (06 §10.1).

## [Unreleased]

### Added

- Phase 11 wrap-up: the client stays LLM-provider agnostic (`promptVersion` and `modelId` are opaque strings; no provider name in `apps/taro/lib/data/`). `SecureIdGenerator` now runs the `taro_core` `IdGenerator` contract suite. `X-Taro-Flavor` (dev/staging only, informational) added to GLOSSARY §4.1 and 03 §2.1; GLOSSARY §9.1 lists `ConsentStoreImpl` separately from `SettingsRepositoryImpl`. `docs/ARCHITECTURE.md` gains the data-layer section (interceptor chain, balance rule, purchase outbox) and `docs/TESTING.md` the Worker contract-fixture section. Reading-route contract fixtures follow in Phase 8.
- Phase 11.4, state repositories: `BalanceRepositoryImpl` (drift-backed `watch`, coalesced `sync`, one RC67 `apply` in a single transaction; a stale `GET /v1/balance` answered after a reading never overwrites the post-reading balance), `RemoteConfigRepositoryImpl` (`If-None-Match` ETag, 304 keeps the cache, offline → last cached or `RemoteConfig.defaults`), `SettingsRepositoryImpl` (one row per backup key plus device-only `reduceMotion`), `ConsentStoreImpl` (`consent_state` JSON, empty → `ConsentState()`), `DailyCardRepositoryImpl` (one card per device-local day, race-safe), `EntitlementCacheImpl` and `PurchaseOutboxImpl` (enqueue before verify, JWS/Play token never logged, finished rows pruned after 30 days), with the shared `SerialValue` helper so wipes and imports done outside a repository are picked up.
- Phase 11.3, Worker client: `WorkerClient` (dio; never throws, returns `Result`) with `Endpoints` (RC4, E02–E17), `ApiTimeouts` (reading 60 s, RC31; poll 1/2/4/8 s within 30 s), the interceptor chain `HeadersInterceptor` → `AuthInterceptor` (single-flight token refresh, re-register hook) → `AttestationInterceptor` (`aa1.`/`pi1.`/`none` over the exact sent bytes) → `AiConsentInterceptor` (RC28) → `RetryInterceptor` (≤ 3 attempts, jittered backoff capped at 8 s, `Retry-After` ≤ 30 s) → `ErrorInterceptor` (`ApiErrorMapper`, unknown code → `ServerFailure`, 426 → `UpgradeRequiredFailure`), `ServerClockTracker` fed from every `Date` header, `json_serializable` DTOs and mappers (`BalanceDto`, `HoldDto`, `ReadingResponseDto`, declined → `refused(SafetyInfo)`), and `test/contract/contract_fixtures_test.dart`, which decodes all 39 Worker fixtures and re-encodes every request fixture against `worker/openapi/openapi.json`.
- Phase 11.4, reading and journal repositories and Worker gateways: `ReadingRepositoryImpl` (pre-draw hold and renewal, the reading persisted `pending` before `POST /v1/readings`, `GET` polling at 1/2/4/8 s within 30 s after a timeout, `409 HOLD_CONFLICT` / `402` keep the draw face-down for a resubmit with the same `clientReadingId`, `410` and `503 AI_UNAVAILABLE` stored as refunded failures, delivered readings queued in `pending_acks` before the ack, resume, 5-second undo of a delete), `JournalRepositoryImpl` (merged newest-first journal with favourite, spread, daily-card and card filters; FTS5 search plus localized card names), `PurchaseVerifierImpl` (transfer token sent and returned on `409 PURCHASE_ALREADY_CLAIMED`), `RewardGatewayImpl`, `ReportGatewayImpl` and `DataDeletionGatewayImpl` (retry queue under `sync_state` key `pending_erasure`). Each passes its `taro_core` contract suite against an in-memory fake Worker.
- Phase 11.5, backup codec: `BackupCodec` (encodes the exportable journal as `taro.backup` v1 inside the `data` wrapper with the RFC 8785 JCS SHA-256 checksum; decodes size → JSON → format → version → `BackupMigrator` → `BackupValidator` in a background isolate), `BackupMigrator` (stepwise chain, empty for v1, pattern tested with a synthetic v0), `JournalBackupStore` (Merge/Replace import as read → `BackupMerge` → write in one drift transaction; also backs `JournalRepository.snapshot/replaceAll`), `JournalRowMapper` (lossless drift row ↔ domain mapping), the byte-identical `lib/data/backup/backup_schema_v1.json` and the golden fixture `test/fixtures/backup_v1_sample.json`.
- Phase 11.2, secure storage and install identity: `SecureKeys`, `FlutterSecureStore` (iOS `first_unlock_this_device`, Android encrypted prefs without a silent reset), `SecureSessionTokenStore`, `InstallRepositoryImpl` (ID and 32-byte secret written together first, `StorageFailure` without a second ID, registration via challenge → device signal → App Attest / Play Integrity or `type: none` proof of work with a fresh `Idempotency-Key` per attempt, purchase binding and key ID in secure storage, the `install_registration` marker in `sync_state`, re-registration with the same ID and secret on `keyInvalidated` or an expired session, `PUT /v1/installs/me/timezone` keeping the server boundary on `409`) and `SecureIdGenerator` (uuid v4 over `CryptoRNG`).
- Phase 11.1, drift databases: `JournalDatabase` (`taro_journal.db`: `readings`, `reading_cards`, `daily_cards`, `settings`, FTS5 trigram `journal_fts` + `journal_search_refs` kept by triggers) and `DeviceDatabase` (`taro_device.db`: `balance_cache`, `remote_config_cache`, `entitlements`, `purchase_outbox`, `consent_state`, `sync_state`, `pending_acks`), SQL schemas in `.drift` files, DAOs (`ReadingsDao` incl. journal search, `DailyCardsDao`, `SettingsDao`, `CacheDao`, `EntitlementsDao`, `OutboxDao` with 30-day prune, `PendingAcksDao`), `shareAcrossIsolates` + WAL, schema v1 dumps in `apps/taro/db/schema/` with `SchemaVerifier` tests, and the RC75 restore simulation. New `taro_core` port `BackupExclusion` (`NoOpBackupExclusion`, `FakeBackupExclusion`, contract suite) with the iOS adapter `PlatformBackupExclusion` and `BackupExclusionPlugin`; Android backup rules now name only `taro_device.db*`. `drift` is pinned to 2.34.0 and `path_provider` is a direct dependency.
- Phase 7, Worker credits, purchases and rewarded ads (code complete, run locally only; details in [worker/CHANGELOG.md](worker/CHANGELOG.md)): `BalanceService.hold/refund/commit` over one conditional D1 batch, `POST /v1/purchases/verify` (App Store Server API + JWS to Apple Root CA G3, Play Developer API, RC63 sandbox caps, RC85 transfer codes), `POST /v1/webhooks/{appstore,googleplay}` with `RefundService` (negative paid → `paidBlocked`, refund-block threshold), rewarded ads (`/v1/rewards/intents*`, `GET /v1/ads/admob/ssv`), the store and reward crons, the owner CLIs `credits-transfer`, `ledger-adjust` and `metrics`, new contract fixtures synced to the app, and `docs/runbooks/SUPPORT_CREDITS.md`. Store credentials, the staging deploy and webhook registration are Phase 10.
- Phase 6, Worker foundation (code complete, run locally only; details in [worker/CHANGELOG.md](worker/CHANGELOG.md)): `.gitea/workflows/worker-deploy.yml` (staging on `main`, 10 % production canary on tag `worker-v*`, manual promotion; skips with a warning until Cloudflare credentials and real binding IDs exist), `tools/worker_smoke.sh`, the OpenAPI and config-schema drift checks in `reusable-static.yml`, the Worker contract fixtures synced to `apps/taro/test/contract/fixtures/` by `melos run contract:sync`, and `docs/runbooks/{WORKER_ROLLBACK,SECRET_ROTATION}.md`. - Phase 5, deck content (English drafts): `apps/taro/content/source/` with `deck.yaml`, `glossary.yaml` (12 locales), all 78 `en` cards, `en/spreads.yaml` (6 spreads), `en/articles/{about,faq}.md` and `crisis/crisis_resources.yaml` (every entry `verifiedAt: null`). ### Fixed

- `tools/check_coverage.py`: a TypeScript type alias whose union or intersection starts with an object type (`type R =\n  { … } | F;`) no longer counts as executable code, so type-only ports such as `worker/src/ports/StoreApis.ts` are not reported as missing from the coverage report (QA4).
- `check_coverage.py` no longer reports Dart files holding only interfaces, plain enums or freezed declarations as missing (QA4). `check_glossary.py` reads enhanced `RefusalCategory` enums.
