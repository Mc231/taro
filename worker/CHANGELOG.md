# Changelog

All notable changes to the Taro Worker (`taro-api`) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `npm run smoke` (`src/admin/smoke.ts`): with `DEBUG_ATTESTATION_TOKEN` on dev/staging, after the balance read it now runs one real single-card reading: `POST /v1/readings/holds` → `POST /v1/readings` (`Idempotency-Key == clientReadingId`, debug attestation, `X-Taro-AI-Consent` from `ai.consentVersion`) → `POST /v1/readings/{id}/ack`, reporting status, latency, classification, charge source, prompt version, balance after and an 80-character text excerpt. A declined reading, `402` or `503` fails the run; error lines include `details.reason` / `details.tier`.
- Safety hardening after the `openai/gpt-6-luna` safety eval (2026-10-01): `ai.moderation.provider` now defaults to `openai` (`omni-moderation-latest`, free; the question after L1 and before the model, an answered output before L3; errors never block; already in `ai.disclosedProviders`, so config validation is unchanged; tier routing untouched). New L1 rules designed on half of the failing eval cases: high-precision `sh.insurance` (en, ar, ja, ko, tr: one's family better off with the insurance money), `sm.secret_child` (en, ar, de, ja: a secret shared with a camp kid or little child), `sm.trust_alone` (en, es, it, ko, pt, tr, uk: getting a child of a stated age under 18 to trust you enough to be alone with you) and `sm.alone_with_child` (en, es, fr, ko, tr: being alone with the neighbours' little girl), each with family `unless` guards; hints `sh.hint.burden` (en, ar), `sm.hint.child_secret` (en), `sm.hint.tutoring` (ja), `sm.hint.alone_neighbour` (nl), `sm.hint.stepchild_age` (uk) and `de.hint.accident` (en, ko: crash or accident predictions). No benign control in `evals/safety/prompts.jsonl`, `evals/cases/quality.jsonl` or the regression corpus changes; the corpus records the new L1 decisions and gains 16 benign `l1guard` controls (life insurance, our secret with a friend, a niece staying over, a parent's insurance money). Live evals take `--moderation none|openai` (needs `OPENAI_API_KEY`): production-order moderation with `moderation_block` / `moderation_flagged` outcomes and the call count in the report and `summary.json`.

- Phase 7.1 ledger and consumption: `BalanceService.hold/refund/commit` (03 §5.3). A hold is one D1 batch holding the free, bonus and paid paths, each gated by a compare-and-set on `readings.hold_state` + `attempt` that carries its balance condition (`free_used < MAX(free_limit, current)`, the Android `device_daily_usage` counter, or `SUM(ledger) >= 1`), with the follow-up writes chained on `(SELECT changes()) = 1` (`src/repos/batchGuard.ts`; spike in `test/integration/db/batchConditional.test.ts`, docs/ARCHITECTURE.md §Ledger). Live holds are renewed, expired ones refunded and replaced by a new attempt; no credit → `no_credit` and a `402 INSUFFICIENT_CREDITS` result with `details.freeResetsAt` and `details.reason` (`noCredits | lowTrustCap | freePaused`). Refunds use the hold's own `hold_local_date` on both usage tables or a `reading_refund` / `reading_undelivered` entry for `{readingId}#{attempt}`; a commit after a cron refund re-holds a new attempt in the same batch or logs `commit_after_refund`.
